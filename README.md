# BPB VPN — Windows port (work in progress)

This repository is a GPL-3.0 fork of [bia-pain-bache/BPB-VPN](https://github.com/bia-pain-bache/BPB-VPN).
The upstream Android app is preserved while a Windows desktop target is added.

## Current status

**A regular Windows x64 GitHub Release is now produced by CI. It is still an experimental proxy-mode client, not a full VPN/TUN implementation.**

The branch now contains an initial Windows proxy-mode controller. It starts the bundled Xray
process, waits for the local mixed inbound, applies the current-user WinINet proxy, and stores
the previous proxy values so they can be restored on disconnect or recovered at the next app
launch. A stale process marker is used to terminate an orphaned Xray process.

This code has not yet passed a complete Windows CI build or a manual Windows connect/disconnect
test. Do not treat the current branch as a working release until those checks pass.

### Windows support matrix

| Feature | Current state |
|---|---|
| Flutter desktop shell | Generated by CI |
| Xray local proxy mode | CI-built; real Windows routing test still required |
| System proxy apply/restore | Implemented with recovery; real Windows validation still required |
| VPN/TUN mode | Not implemented |
| Psiphon / Tor exits | Not implemented |
| Browser Dialer | Not implemented |
| Tray, installer, auto-start | Not implemented |
| Windows path-MTU diagnostics | Implemented; real Windows validation pending |
| Iran routing preset | Implemented using existing geo/routing rules; verify bundled geo data |

The first usable Windows release is intended to be **proxy mode only**, without administrator
rights. TUN mode is a later milestone.

The Windows client remains an experimental system-proxy client, not a full-device VPN. A Path MTU Finder is available under Settings on Windows; it reports an estimate only and does not change network settings. Settings also includes an Iran routing preset based on the existing bundled geo rules.

## Build preview locally

Requirements: Windows 10/11 x64, Visual Studio 2022 with the Desktop development with C++ workload,
Flutter stable, Go matching xray/go.mod, Node.js, and Git.

```powershell
flutter create --platforms=windows --project-name bpb .
if (Test-Path test/widget_test.dart) { Remove-Item test/widget_test.dart -Force }
Push-Location worker
npm install --no-package-lock --no-audit --no-fund
npm run minify
Pop-Location
bash scripts/fetch_tor_bridges.sh
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
flutter build windows --release
bash scripts/fetch_geo.sh
./scripts/build_xray_windows.ps1
./scripts/package_windows.ps1
```

The app is written under build/windows/x64/runner/Release/. The staged Xray executable and
geo databases are placed in its data/ subdirectory.

The GitHub Actions workflow uploads a short-lived preview artifact. It does not create a GitHub
Release. A successful compile alone does not prove that proxy routing and restoration work on a
real Windows machine.

## Safety and project notes

- Android remains the upstream platform; keep its behavior unchanged.
- Windows VPN/TUN mode is not supported. Select the app's **Proxy** mode for the experimental path.
- The Windows controller changes the current user's WinINet proxy settings and must restore them.
  If testing fails, close the app and inspect Windows Settings → Network & internet → Proxy.
- Do not commit API tokens, private bridge credentials, signing keys, or certificates.
- Keep upstream attribution and GPL-3.0 licensing. Distributed binaries must include the
  corresponding source and license notices.
